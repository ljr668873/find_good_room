# 部署文档

两种方式二选一：**Docker Compose**（推荐，一条命令起全套）或**裸机部署**（已有 MySQL/Nginx 的机器）。

前置准备（两种都需要）：

```bash
cd web && npm install && npm run build   # 产出 web/dist
```

---

## 方式一：Docker Compose

### 1. 配置环境变量

```bash
cd deploy
cp .env.example .env
# 编辑 .env，修改 DB_PASSWORD / JWT_SECRET / ADMIN_PASSWORD
```

### 2. 启动

```bash
docker compose up -d --build
```

首次启动需初始化数据库（表结构 + 城市与管理员账号，幂等可重复执行）：

```bash
docker compose exec api alembic upgrade head
docker compose exec api python -m scripts.seed
```

### 3. 验证

```bash
curl http://localhost/api/health        # {"status":"ok"}
curl http://localhost/                  # 前端页面
```

### 日常运维

```bash
docker compose up -d --build            # 发布新版本（重新构建 + 滚动重启）
docker compose logs -f api              # 看日志
docker compose down                     # 停止（数据卷保留）
docker compose down -v                  # 停止并清空数据（危险）
```

数据持久化：MySQL 在 `mysql_data` 卷，房源照片在 `uploads` 卷。

## 方式二：裸机部署

**推荐用脚本**（Linux + systemd + nginx，重复执行即更新发布）：

```bash
# 项目放到服务器后：
cd deploy
cp .env.example .env && vi .env      # 改密码/域名等
sudo bash deploy-bare.sh
```

脚本做的事：同步文件到 `INSTALL_DIR` → venv 装依赖 → 生成运行时配置（600 权限）→ 迁移+种子 → 写 systemd unit 并启动 → 写 nginx conf 并 reload → 健康检查。前端无 node 时用提前构建好的 `web/dist`，有 node 则现场构建。

以下手动步骤与脚本等价，供理解与排障：

前置：Python 3.12、MySQL 8+、Node 20+（仅构建时）、Nginx。

### 1. 数据库

```sql
CREATE DATABASE find_good_room CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

### 2. 后端

```bash
cd server
python3 -m venv .venv
.venv/bin/pip install -e .
export DB_HOST=127.0.0.1 DB_USER=root DB_PASSWORD=你的密码 DB_NAME=find_good_room
export JWT_SECRET=随机长字符串
.venv/bin/alembic upgrade head
ADMIN_USERNAME=admin ADMIN_PASSWORD=你的密码 .venv/bin/python -m scripts.seed
```

systemd 服务（`/etc/systemd/system/find-good-room.service`）：

```ini
[Unit]
Description=find_good_room API
After=network.target mysql.service

[Service]
WorkingDirectory=/opt/find_good_room/server
Environment=DB_HOST=127.0.0.1
Environment=DB_USER=root
Environment=DB_PASSWORD=你的密码
Environment=DB_NAME=find_good_room
Environment=JWT_SECRET=随机长字符串
ExecStart=/opt/find_good_room/server/.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8000
Restart=always

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl enable --now find-good-room
```

### 3. 前端静态文件 + Nginx

```bash
sudo mkdir -p /var/www/find_good_room
sudo cp -r web/dist/* /var/www/find_good_room/
```

Nginx 站点配置（`/etc/nginx/conf.d/find_good_room.conf`）：

```nginx
server {
    listen 80;
    server_name 你的域名或IP;
    client_max_body_size 100m;

    location /api/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }

    location /uploads/ {
        proxy_pass http://127.0.0.1:8000;
    }

    location / {
        root /var/www/find_good_room;
        index index.html;
        try_files $uri $uri/ /index.html;
    }
}
```

```bash
sudo nginx -t && sudo systemctl reload nginx
```

## 环境变量一览

| 变量 | 默认值 | 用在哪 |
|------|--------|--------|
| `DB_HOST` / `DB_PORT` / `DB_USER` / `DB_PASSWORD` / `DB_NAME` | 127.0.0.1 / 3306 / root / — / find_good_room | 后端数据库连接（start.sh、systemd、docker-compose 的 api 容器） |
| `API_PORT` | 8000 | 后端监听端口（start.sh → uvicorn，vite 代理目标同步读取） |
| `WEB_PORT` | 5173 | 前端 dev server 端口（start.sh → vite） |
| `HTTP_PORT` | 80 | docker-compose 的 nginx 对外端口（deploy/.env） |
| `JWT_SECRET` | dev-secret-change-me | 登录令牌签发密钥（生产必改） |
| `ADMIN_USERNAME` / `ADMIN_PASSWORD` | admin / admin123456 | seed 脚本创建的管理员账号 |

说明：

- **本地开发**：start.sh 里统一 export，vite.config.js 读取同一 `API_PORT`/`WEB_PORT`，改一处全生效
- **docker-compose**：容器间内部端口（api:8000）为固定约定不暴露，对外只有 nginx 的 `HTTP_PORT`
- **裸机部署**：改 `API_PORT` 需同步修改 systemd unit 的 `ExecStart` 与 nginx `proxy_pass` 两处（见上文配置块）
- 前端构建产物（web/dist）内只有相对路径 `/api`，无端口硬编码，nginx 同源代理，换端口无需重新构建

## HTTPS（生产必做）

有域名时用 certbot 一键加证书：

```bash
sudo certbot --nginx -d 你的域名
```

## 安全清单

- [ ] `.env` / systemd 中的 `JWT_SECRET`、`DB_PASSWORD` 均已改为随机值
- [ ] `ADMIN_PASSWORD` 已修改（默认 admin123456 仅限本地开发）
- [ ] 生产环境 HTTPS 已开启（登录 token 明文传输依赖 HTTPS 保护）
- [ ] MySQL 未暴露公网端口（compose 版默认仅内网；裸机版勿 bind 0.0.0.0）
