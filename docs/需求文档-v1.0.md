# 城中村租房平台 MVP 需求文档

> 版本：v1.0
> 日期：2026-09-29
> 状态：定稿

---

## 1. 项目概述

### 1.1 定位

面向大城市城中村的租房信息平台，连接**个人房东/二房东**与**租客**，只做信息展示与连接，不介入交易。

### 1.2 要解决的问题

| 痛点 | 现状 | 本平台做法 |
|------|------|-----------|
| 过期房源干扰 | 房子租出去了信息还挂着 | 房东标记已租，立即从列表消失 |
| 隐藏成本坑 | 商水商电、杂费签约后才知道 | 水电单价为必填字段，列表页即可见 |
| 城中村房源覆盖差 | 主流平台以小区房为主 | 专注城中村，按村名/地铁站组织房源 |
| 界面杂乱广告多 | 信息流干扰决策 | 无广告、无推荐流，纯列表 |

### 1.3 核心价值主张

**真实、干净、直联房东。**

### 1.4 目标用户

- **租客**：在大城市工作的年轻租房人群，价格敏感，手机上网为主，决策周期短（看到—打电话—去看房，常在同一天完成）
- **房东**：城中村村民、二房东，管理几套到几十套房，不熟悉复杂软件，需要极简的发布流程

---

## 2. 用户角色

| 角色 | 注册要求 | 能做什么 |
|------|---------|---------|
| 租客 | **无需注册** | 浏览、筛选、搜索、查看联系方式、查看房东主页 |
| 房东 | 用户名 + 密码 | 发布、管理、上下架房源 |
| 管理员 | 内部账号 | 下架违规房源、处理举报 |

**关键决策：租客免注册。** 纯信息平台的转化路径要最短——城中村租客的习惯是看到合适的直接打电话。任何登录墙都会流失用户。

## 3. 租客端功能（找房）

### 3.1 房源列表页（首页）

- 卡片式列表：封面图、租金（醒目）、户型、村名/位置、距地铁信息
- 卡片角标状态：`在租`（正常）/ `新`（发布 3 天内）
- 下拉自动加载下一页（每页 20 条）
- 顶部常驻：搜索框 + 筛选入口

### 3.2 筛选

| 筛选项 | 形式 |
|--------|------|
| 城市 | 顶栏城市切换器，选择后记忆（localStorage），所有列表/筛选/搜索均限定在当前城市 |
| 村名 | 下拉：当前城市下有房源的村名聚合，按房源数排序 |
| 地铁站 | 下拉：当前城市下有房源的地铁站聚合，按线路分组 |
| 租金区间 | 快捷档（≤800 / 800-1500 / 1500-2500 / 2500+）+ 自定义 |
| 户型 | 单选：单间 / 一房一厅 / 两房 / 隔断间 |
| 独立卫浴 | 开关（默认不限） |
| 押付方式 | 押一付一 / 押一付三 / 押二付一 / 不限 |
| 楼层 | 有电梯 / 不限 |

筛选条件变更后立即刷新列表，并显示可一键清除的条件标签。

MVP 支持的城市列表写在配置里（首个城市按实际落地城市定），后续由管理员在后台增改，不做开放注册。

### 3.3 搜索

- 关键词匹配：村名、地铁站名、标题
- 搜索范围限定在当前城市
- 搜索历史不保存（MVP 不做，见第 7 节）

### 3.4 房源详情页

- **照片轮播**：最多 9 张，手势滑动，点击全屏
- **核心信息区**：租金、押付方式、户型、面积、楼层、可入住时间
- **硬需求区**：独立卫浴（是/否）、水费单价、电费单价
- **位置区**：村名、详细位置文字描述、距地铁（线路+站名+步行分钟）。MVP 不接地图 JS API，用文字描述
- **联系方式区**：电话（点击直接拨号 `tel:` 链接）、微信号（如有，点击复制）
- **底部固定操作条**：`拨打电话` 主按钮
- **举报入口**：底部次要链接，选原因（虚假房源/已租出/信息错误/其他），提交后进入管理员队列
- **房东主页入口**："看 TA 的全部房源" 链接，进入房东主页（见 3.5）

### 3.5 房东主页

两种浏览范围：全量房源（首页）与单个房东名下房源（房东主页）。

- **入口**：房源详情页，点击房东信息区 "看 TA 的全部房源"
- **页面内容**：房东用户名、在租房源数量、该房东名下全部在租房源列表（复用房源卡片）
- **筛选与搜索**：复用全量列表的筛选/搜索组件，作用范围限定在该房东名下
- **不做**：关注房东、房东简介、评价（YAGNI）

### 3.6 明确不做（MVP）

收藏、浏览历史、地图找房、IM 聊天、订阅通知。见第 7 节。

## 4. 房东端功能（后台）

### 4.1 注册与登录

- 用户名 + 密码注册，用户名唯一，密码至少 6 位
- 无手机验证、无邮箱验证，注册即可发布
- 联系电话在发布房源时单独填写（见 4.2），与登录账号解耦
- 登录态保持 30 天

### 4.2 发布房源

表单分 3 步（移动端友好）：

1. **基本信息**：城市（必选，从支持城市列表选择）、村名（可搜索选择或自由输入）、租金、户型、押付方式、面积、楼层/总层、朝向采光
2. **硬需求与配套**：独立卫浴、水费单价、电费单价、可入住时间、近地铁（选填）、周边描述（选填）
3. **照片与联系方式**：上传照片（最多 9 张，前端压缩至 500KB/张，第 1 张为封面）、联系电话（必填）、微信号（选填）、自定义标题（不填自动生成：`{村名}·{户型}·{租金}`）

必填项未完成不能进入下一步。提交后直接上架。

### 4.3 房源管理

- 我的房源列表：按状态分组（在租 / 已下架 / 已租出）
- 单条操作：编辑、下架、重新上架、标记已租
- 标记已租后房源立即从租客端消失，但数据保留，可一键复制重新发布

## 5. 房源字段定义

可直接映射为数据库表设计。

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | 主键 | 自动 | 房源唯一标识 |
| landlord_id | 外键 | 自动 | 关联房东 |
| title | 文本(50) | 否 | 不填自动生成 `{村名}·{户型}·{租金}` |
| city | 文本 | 是 | 城市，从平台支持的城市列表选择 |
| village | 文本 | 是 | 村名，如"白石洲"、"客村" |
| address | 文本(100) | 是 | 详细位置文字，如"X 巷 X 号 3 楼" |
| rent | 整数 | 是 | 月租金（元） |
| deposit_type | 枚举 | 是 | 押一付一 / 押一付三 / 押二付一 |
| layout | 枚举 | 是 | 单间 / 一房一厅 / 两房 / 隔断间 |
| area | 数值 | 是 | 建筑面积（㎡） |
| floor / floor_total | 整数 | 是 | 所在层 / 总层数 |
| has_elevator | 布尔 | 是 | 是否有电梯 |
| facing | 文本 | 否 | 朝向与采光描述 |
| private_bathroom | 布尔 | 是 | 独立卫浴（城中村核心关切） |
| water_price | 数值 | 是 | 水费单价（元/吨） |
| electric_price | 数值 | 是 | 电费单价（元/度），商水商电必露 |
| available_date | 日期 | 是 | 可入住时间 |
| metro_line | 文本 | 否 | 地铁线路，如"1 号线" |
| metro_station | 文本 | 否 | 地铁站名，与线路配对填写 |
| walk_minutes | 整数 | 否 | 距地铁站步行分钟数 |
| surroundings | 文本(200) | 否 | 周边：超市、菜市场等 |
| photos | 图片数组 | 是 | 最多 9 张，第 1 张为封面 |
| phone | 文本 | 是 | 联系电话 |
| wechat | 文本 | 否 | 微信号 |
| status | 枚举 | 自动 | 在租 / 已租 / 已下架 / 待审核 |
| created_at / updated_at | 时间 | 自动 | — |

## 6. 非功能需求

- **移动优先**：所有页面以 375px 宽度为设计基准，PC 端居中自适应（最大 720px 内容区）
- **性能**：首屏 < 2s（4G 网络），图片懒加载，列表接口 < 300ms
- **视觉**：白底、大字号、单一主色（建议绿色系，传达"放心"），无广告位、无弹窗、无诱导按钮
- **图片存储**：上传压缩至 500KB 内，生成缩略图（列表用）与压缩图（详情用）两档

## 7. MVP 边界（明确不做）

防止 scope creep，以下全部 **不做**：

- ~~支付、订金、线上签约~~
- ~~租客账号体系、收藏、浏览历史、IM~~
- ~~地图找房、通勤找房~~
- ~~公寓运营方批量导入、子账号、合同管理~~
- ~~房东信用分、评价体系~~
- ~~小程序 / APP~~
- ~~管理员内容预审~~（MVP 靠举报 + 事后下架，量大了再加预审）

## 附：核心用户流程

```
租客：打开首页 → 筛选/搜索 → 看详情 → 打电话 → 线下看房签约（平台外完成）

房东：注册登录 → 发布房源（3 步表单）→ 接电话 → 租出 → 标记已租
```
