# 城中村租房平台 技术方案 v1.0

> 对应需求：[需求文档-v1.0.md](./需求文档-v1.0.md)
> 日期：2026-09-29
> 技术栈（已定）：后端 MySQL + FastAPI，前端 Vue3

---

## 1. 总体架构

单体应用，一个后端服务 + 一个前端站点，Nginx 统一入口。

```
浏览器
  │
  ▼
Nginx ── 静态文件（Vue3 打包产物 dist/）
  │
  └── /api/* 反向代理 ──▶ FastAPI (uvicorn)
                            │
                            ├── MySQL 8.0
                            └── 本地磁盘 /uploads（房源照片）
```

无消息队列、无缓存层、无对象存储（OSS）。流量到量级前不引入。

## 2. 技术栈清单

### 后端

| 依赖 | 版本 | 用途 |
|------|------|------|
| Python | 3.12 | 运行时 |
| FastAPI | 0.11x+ | Web 框架 |
| SQLAlchemy | 2.0 | ORM（**sync**，非 async） |
| PyMySQL | 最新 | MySQL 驱动 |
| Alembic | 最新 | 数据库迁移 |
| Pydantic | 2.x | 请求/响应模型（FastAPI 内置） |
| PyJWT | 最新 | 登录令牌 |
| passlib[bcrypt] | 最新 | 密码哈希 |
| Pillow | 最新 | 图片压缩 |
| uvicorn | 最新 | ASGI 服务器 |

**为什么 sync ORM**：本项目流量小（同城分类信息站），FastAPI 对 sync 路由自动走线程池，够用且调试简单。异步收益在长连接/高并发 IO，这里没有。

### 前端

| 依赖 | 版本 | 用途 |
|------|------|------|
| Vue | 3.4+ | 框架，Composition API + `<script setup>` |
| Vite | 5+ | 构建 |
| vue-router | 4 | 路由 |
| Pinia | 2 | 状态（token、当前城市） |
| Vant | 4 | 组件库：列表上拉加载、图片懒加载、轮播、表单选择器全覆盖 |
| axios | 1.x | HTTP |

**为什么 JS 不用 TS**：单人小项目，页面 8 个左右，TS 收益低于配置成本。要换 TS 在 Vite 里是一行配置的事，不锁死。

**为什么 Vant 不用 Element Plus**：移动优先（需求 §6），Vant 的 List（无限滚动）、Lazyload、Swipe（轮播）开箱即用，PC 端响应式布局下同样成立。不引第二套组件库。

## 3. 数据库设计

4 张表：`users`、`cities`、`listings`、`reports`。照片存 `listings` 的 JSON 列，不建独立表（单房源最多 9 张、无按图查询场景，一列省一次 join）。

### 3.1 users（房东/管理员）

```sql
CREATE TABLE users (
  id            BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  username      VARCHAR(32)  NOT NULL UNIQUE,
  password_hash VARCHAR(127) NOT NULL,           -- bcrypt
  is_admin      TINYINT(1)    NOT NULL DEFAULT 0,
  created_at    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

### 3.2 cities（支持城市，MVP 用种子脚本录入）

```sql
CREATE TABLE cities (
  id   INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  name VARCHAR(32) NOT NULL UNIQUE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

### 3.3 listings（房源，核心表）

```sql
CREATE TABLE listings (
  id               BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  landlord_id      BIGINT UNSIGNED NOT NULL,
  title            VARCHAR(50)  NOT NULL,        -- 空=后端自动生成 {村名}·{户型}·{租金}
  city             VARCHAR(32)  NOT NULL,
  village          VARCHAR(32)  NOT NULL,
  address          VARCHAR(100) NOT NULL,
  rent             INT UNSIGNED NOT NULL,        -- 月租金（元）
  deposit_type     VARCHAR(16)  NOT NULL,        -- 押一付一/押一付三/押二付一
  layout           VARCHAR(16)  NOT NULL,        -- 单间/一房一厅/两房/隔断间
  area             DECIMAL(5,1) NOT NULL,        -- ㎡
  floor            INT          NOT NULL,
  floor_total      INT          NOT NULL,
  has_elevator     TINYINT(1)   NOT NULL,
  facing           VARCHAR(50)  NULL,
  private_bathroom TINYINT(1)   NOT NULL,
  water_price      DECIMAL(5,2) NOT NULL,        -- 元/吨
  electric_price   DECIMAL(5,2) NOT NULL,        -- 元/度
  available_date   DATE         NOT NULL,
  metro_line       VARCHAR(16)  NULL,
  metro_station    VARCHAR(32)  NULL,
  walk_minutes     INT          NULL,
  surroundings     VARCHAR(200) NULL,
  photos           JSON         NOT NULL,        -- ["/uploads/xx.webp", ...] 第一张为封面
  phone            VARCHAR(20)  NOT NULL,
  wechat           VARCHAR(32)  NULL,
  status           VARCHAR(8)   NOT NULL DEFAULT 'active',  -- active/rented/offline
  created_at       DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at       DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  CONSTRAINT fk_listing_landlord FOREIGN KEY (landlord_id) REFERENCES users(id),
  INDEX idx_city_status_rent   (city, status, rent),
  INDEX idx_city_village       (city, status, village),
  INDEX idx_city_metro         (city, status, metro_station),
  INDEX idx_landlord           (landlord_id, status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

说明：

- 需求文档 §5 的 `待审核` 状态砍掉——MVP 无预审（需求 §7），`status` 只有 `active/rented/offline`
- 列表查询恒带 `city + status='active'`，三个复合索引覆盖主查询路径；房东主页走 `idx_landlord`
- 字段校验（枚举值、面积范围等）由 Pydantic 层做，DB 不加 CHECK（MySQL 8 支持但 ORM 迁移维护两份）

### 3.4 reports（举报）

```sql
CREATE TABLE reports (
  id         BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  listing_id BIGINT UNSIGNED NOT NULL,
  reason     VARCHAR(16) NOT NULL,   -- fake/rented/wrong/other
  status     VARCHAR(8) NOT NULL DEFAULT 'pending',  -- pending/done
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  CONSTRAINT fk_report_listing FOREIGN KEY (listing_id) REFERENCES listings(id),
  INDEX idx_status (status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

## 4. API 设计

REST，统一前缀 `/api`。响应统一 `{ code, msg, data }` 或直接 FastAPI 异常（`HTTPException`），列表分页统一 `?page=&page_size=`，返回 `{ items, total, page, page_size }`。

### 4.1 公开接口（租客，无鉴权）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/cities` | 支持城市列表 |
| GET | `/api/filter-options?city=` | 当前城市筛选项聚合：村名、地铁站（各带在租数量，GROUP BY） |
| GET | `/api/listings` | 房源列表。参数：`city`（必填）、`village`、`metro_station`、`rent_min`、`rent_max`、`layout`、`private_bathroom`、`deposit_type`、`has_elevator`、`keyword`、`page` |
| GET | `/api/listings/{id}` | 房源详情，仅 `status=active` 可见 |
| GET | `/api/landlords/{id}/listings` | 房东主页房源列表，参数同 `/api/listings`（复用同一查询构造器，多一个 landlord_id 条件） |
| POST | `/api/reports` | 提交举报 `{listing_id, reason}` |

### 4.2 房东接口（JWT Bearer）

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/auth/register` | `{username, password}`，密码 ≥6 位，用户名唯一 |
| POST | `/api/auth/login` | 返回 `{token}`，有效期 30 天 |
| GET | `/api/me` | 当前用户信息 |
| POST | `/api/my/listings` | 发布房源 |
| PUT | `/api/my/listings/{id}` | 编辑（校验归属） |
| PATCH | `/api/my/listings/{id}/status` | `{action: offline/active/rented}` |
| GET | `/api/my/listings?status=` | 我的房源，按状态分组由前端处理 |
| POST | `/api/upload/photos` | 照片上传（multipart，≤9 张/次），服务端压缩，返回 URL 数组 |

"已租复制重发"（需求 §4.3）不开专门接口：前端编辑页读取旧房源数据预填表单，提交走 POST 新建。

### 4.3 管理员接口（JWT + is_admin）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/admin/reports?status=` | 举报队列 |
| PATCH | `/api/admin/reports/{id}` | 标记已处理 `{status: done}` |
| PATCH | `/api/admin/listings/{id}/status` | 强制下架 |

管理员账号：种子脚本创建（读环境变量注入的用户名/密码），不做注册入口。

## 5. 后端模块结构

```
server/
├── alembic/              # 迁移
├── alembic.ini
├── app/
│   ├── main.py           # 入口：挂路由、静态目录 /uploads、CORS
│   ├── config.py         # 环境变量：DB URL、JWT secret、上传目录
│   ├── database.py       # engine、SessionLocal、Base
│   ├── models.py         # 4 张表 ORM（一个文件够）
│   ├── schemas.py        # Pydantic 请求/响应模型
│   ├── auth.py           # 密码哈希、JWT 签发校验、get_current_user 依赖
│   ├── deps.py           # 分页参数、列表筛选参数解析
│   └── routers/
│       ├── listings.py   # 公开列表/详情/房东主页/筛选项聚合
│       ├── auth.py       # 注册/登录/me
│       ├── my.py         # 房东发布/编辑/状态/上传
│       └── admin.py      # 举报处理/下架
├── scripts/seed.py       # 建管理员、录入城市
└── pyproject.toml
```

单文件 models/schemas，不上 repositories/services 分层——CRUD 直写在 router，SQLAlchemy 查询即数据层。出现第二处复用逻辑时再提函数。

## 7. 横切方案

### 7.1 认证

- JWT（HS256），payload `{uid, exp}`，secret 走环境变量
- 密码 bcrypt（passlib），登录失败不提示具体原因（统一"用户名或密码错误"）
- 前端 token 存 localStorage，axios 请求拦截器统一加 `Authorization: Bearer`
- 登录接口加简单限流：同 IP 每分钟 10 次（内存计数即可，不上 Redis）

### 7.2 图片

- 上传 multipart → 服务端校验（jpg/png/webp，单张 ≤10MB 原图）→ Pillow 压缩转 WebP（最长边 1600px，质量 80，目标 ≤500KB）→ 随机文件名存 `/uploads/yyyy/mm/` → 返回 URL
- 列表封面另生成缩略图（最长边 480px），文件名加 `_thumb` 后缀，photos JSON 里封面存两项：`["/uploads/a_thumb.webp", "/uploads/a.webp", ...]` —— 约定：第一项缩略图给列表，其余原图给详情轮播
- `/uploads` 由 FastAPI `StaticFiles` 直接挂载（MVP 不让 Nginx 单独处理，少一处配置）

### 7.3 安全线（不可省）

- SQL 注入：全程 SQLAlchemy 参数绑定，无裸 SQL 拼接
- 越权：`/api/my/*` 全部校验 `landlord_id == current_user.id`；详情/列表接口只暴露 active 房源
- 上传：类型白名单 + 大小限制 + 随机文件名（防路径穿越/脚本上传）
- 生产环境：Nginx 强制 HTTPS（证书 Let's Encrypt）

## 8. 部署

单机 docker-compose，三个服务：

```yaml
services:
  mysql:    # mysql:8.0，数据卷持久化，健康检查
  api:      # uvicorn app.main:app --workers 2，依赖 mysql 健康
  nginx:    # 80/443：托管 web/dist 静态文件，/api 与 /uploads 反代 api:8000
```

- 前端 `vite build` 产物挂载进 nginx
- Alembic 迁移与种子脚本在 api 容器启动后执行一次（compose 的一次性 job 或手动 `docker compose exec`）
- 不做 CI/CD、不做多环境——单机 `docker compose up -d --build` 即发布
